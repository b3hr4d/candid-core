Seven wallets.
Six interfaces. One frontend.

Every user of this dapp owns their own wallet canister and upgrades it when they feel like it — or never. So the fleet is permanently spread across versions, and the frontend has to work anyway. Below, that frontend figures out what each wallet can do by compiling its DID interface right here in this page and comparing canonical identities. No server, no registry, no version string it has to take on trust.

05 How this page works

Nothing is precomputed

The page fetches plain .did files, hands each bundle to compile_with_resolver through a MemoryResolver, and renders what comes back. Delete the .wasm and there is nothing left to show.

No filesystem, no ambient authority

The module is built with default-features = false and only the compiler feature — no cap-std, nothing that could read a file. An import the page did not supply is a resolver error, never a fetch.

No binding generator

candid-core takes no wasm-bindgen production dependency, so neither does this. The bridge is four extern "C" functions over linear memory and one JSON document each way.

Every limit still applies

The same interactive_v1 bounds the CLI uses hold here. Paste a megabyte of padding into the editor and you get a structured resource_limit_exceeded, not a hung tab.

An actor is an object with one async method per canister method. You build it from a service schema, call await actor.balance_of(account), and get back the decoded reply. The object is plain data assembled at construction time, not a class instance: each method is a closure that encodes its arguments, hands the bytes to a transport, and decodes what comes back.

What separates this layer from a conventional agent binding is where the Candid encoding lives. The actor owns it, using the package's own binary codec. The network layer is an interface with exactly two methods that move Uint8Array in and Uint8Array out, so whatever implements it never sees a schema and never learns anything about your types. That split is what lets you drive an actor from a plain object literal in a unit test, and swap the network without touching a single call site.

createActor

createActor @candid-core/schema/actor 
export function createActor Promise>>(
  service: AnyFieldSchema,
  canisterId: string,
  transport: Transport,
  options: ActorOptions = {},
): A

Walks the service schema's method table once and installs one async method per canister method, keyed by name, in the order the schema itself lists them. Throws TypeError straight away if service does not resolve to a service schema.

The methods come from serviceMethods, the same walk you can run yourself, so the table you can inspect and the table the actor dispatches on cannot disagree. For a generated module that order is the Contract's canonical one — methods sorted by Candid label id, which is the hash of the method name — not the order the methods appear in your .did. The returned object is built with Object.create(null), which matters because Candid admits method names such as __proto__ and toString: with no prototype in the way, those are ordinary own properties.

Why the interface type is passed explicitly

Generated modules wrap every declaration in c.rec(() => …), a lazy thunk that makes recursive types and forward references safe. That wrapper erases method structure from the schema's static type, so typeof actorSchema cannot tell TypeScript which methods exist. The call interface therefore travels as its own export, export type Actor = { … }, and you pass it as createActor<Actor>(…). The two stay in step because the generator emits both from the same Contract — this project's validated, canonical model of a .did interface — and the test suite pins the emitted Actor against a hand-written interface with a type-level equality check.

ActorOptions has one field, effectiveCanisterId, copied into every call target the actor builds.

The Transport interface

This is the whole network contract. Two async methods, taking a call target plus Candid-encoded argument bytes, resolving to Candid-encoded reply bytes.

/** Where a call goes; `effectiveCanisterId` only matters for system routing. */
export interface CallTarget {
  readonly canisterId: string;
  readonly methodName: string;
  readonly effectiveCanisterId?: string;
}

/** Candid-encoded bytes in, Candid-encoded reply bytes out. */
export interface Transport {
  /** Non-replicated read path: `query` and `composite_query` methods. */
  query(target: CallTarget, arg: Uint8Array): Promise;
  /** Replicated certified path: `update` and `oneway` methods. */
  call(target: CallTarget, arg: Uint8Array): Promise;
}

effectiveCanisterId exists for management-canister routing, where a request is addressed to aaaaa-aa but has to reach the subnet hosting the canister being acted on. When it is absent, a call routes to canisterId.

How each method mode dispatches

Every Candid method declares a mode, and the actor turns that mode into a choice of transport method. The whole decision sits in dispatch:

const viaQuery = func.mode === "query" || func.mode === "composite_query";
const reply = viaQuery
  ? await transport.query(target, encoded.bytes)
  : await transport.call(target, encoded.bytes);

update is the unannotated default, made explicit in the Contract and in the generated schema. A oneway method is dispatched and awaited exactly like an update: the reference agent has no separate oneway path, and inventing one here would invent semantics the platform does not offer. A oneway call resolves to undefined.

Calling a real canister

The adapter from Transport to @icp-sdk/core's HttpAgent ships compiled and tested as its own subpath, so it is written once here rather than re-derived by every consumer against a moving agent API.

httpTransport @candid-core/schema/transport-icp 
export interface HttpTransportOptions {
  readonly rootKey?: Uint8Array;
  readonly host?: string;
  readonly agent?: Agent;
}

export function httpTransport(options: HttpTransportOptions = {}): Transport

Three options and no more. host is the replica URL and defaults to the page origin. rootKey is the key certificates are verified against — needed on a local network, omitted on mainnet, whose root key the agent already knows. agent supplies a pre-built agent for everything else, including identity, and must travel alone: combining it with host or rootKey throws TypeError, because configuring a supplied agent from here would silently discard what it was built with.

httpTransport returns its Transport synchronously; the agent is created once and awaited inside each call. query calls agent.query; call calls agent.update and returns result.reply. The peer range >= 6 is load-bearing for that second line: on v6 the agent submits, polls to completion, and verifies the certificate before resolving, so those bytes are the certified reply. Older majors resolved update at submission and need their own submit-and-poll adapter, deliberately not written here.

@icp-sdk/core is declared as a peer dependency at >=6 with "optional": true in peerDependenciesMeta. npm install @candid-core/schema pulls in nothing extra and warns about nothing. Importing @candid-core/schema/transport-icp is the moment the SDK becomes a real runtime requirement, and you install it yourself. Every other subpath compiles and runs with no SDK present, in your runtime and in your types. This subpath also carries its own Node floor of 20.19, which is what the pinned SDK dependency tree's own engines declare; the other seven subpaths are exercised from Node 16 up.

End to end

This uses the generated module for the ICP ledger interface — the same one the repository keeps as a golden. It exports actor (the runtime service schema the factory walks) and Actor (the static call interface you type the result with), alongside a type alias and schema for each declaration.

import { createActor, ActorError } from "@candid-core/schema/actor";
import { httpTransport } from "@candid-core/schema/transport-icp";
import * as ledger from "./ledger.ts"; // the generated module

const icrc = createActor(
  ledger.actor,
  "ryjl3-tyaaa-aaaaa-aaaba-cai",
  httpTransport({ host: "https://icp-api.io" }),
);

// query mode, so this rides transport.query
const symbol: string = await icrc.symbol();

// A principal is anything whose toText() returns canonical principal text.
// The SDK's Principal satisfies that structurally, and so does this.
const recipient = { toText: () => "ryjl3-tyaaa-aaaaa-aaaba-cai" };

try {
  // update mode, so this rides transport.call and the reply is certified
  const outcome: ledger.TransferResult = await icrc.transfer({
    to: { owner: recipient, subaccount: null },
    fee: null,
    memo: null,
    from_subaccount: null,
    created_at_time: null,
    amount: { e8s: 7n },
  });

  if (outcome.tag === "ok") {
    const blockIndex: bigint = outcome.value;
    console.log(`${symbol} transferred in block ${blockIndex}`);
  } else {
    console.error("the ledger refused the transfer:", outcome.value);
  }
} catch (error) {
  if (error instanceof ActorError) {
    // A codec failure: the value did not match the schema.
    for (const issue of error.issues) {
      console.error(issue.code, issue.path, issue.message);
    }
  } else {
    // A transport failure, propagated untouched.
    throw error;
  }
}

Adjust the import specifier for the generated module to whatever your module resolution expects. Read the argument literal closely, because it is the domain model this project chose: every opt field is T | null rather than the [] | [T] array agent-js uses, and TransferResult is a { tag, value } discriminated union rather than a single-key object. The mapping reference has the full table, and compatibility with agent-js shapes is an explicit non-goal.

Decoded principals follow the same rule in reverse: the codec never constructs an SDK class, so a decoded principal carries exactly toText(). instanceof Principal is false and .toUint8Array() does not exist on it. Re-wrap with Principal.fromText(value.toText()) when you need the class.

When a call fails

There are three distinct failure styles, and telling them apart is deliberate.

ActorError — a rejected promise
The codec refused to encode an argument or decode a reply. The message names the stage ("encode" or "decode") and the method; issues carries the codec's structured failures, each with a stable code, a $-rooted path ($args[i] per argument), and a message — the same code/path/message convention the Rust crate's diagnostics carry, on a narrower record. An argument that fails to encode rejects before anything crosses the transport, so a bad call never reaches the replica.
TypeError — thrown synchronously
Misuse of the API itself, raised at the call that made the mistake rather than at some later await. Passing a non-service schema to createActor, or combining a pre-built agent with host or rootKey in httpTransport, both land here.
Anything the transport throws — propagated unchanged
Network failures are not wrapped. Neither are replica rejects: when the replica rejects a query, the ICP adapter throws a plain Error whose message is `${methodName} rejected (${reject_code}): ${reject_message}`. There is no reject class to catch and no parsed reject payload on the error object. Classifying rejects stays on the agent's side of the pipe; if you want structured handling, write it around the transport.

Writing your own transport

Two methods is the entire obligation, so a transport can be an object literal. This is a complete one, from the introspection test — enough to build an actor and check its shape without a network, an agent, or a canister:

const transport: Transport = {
  query: () => Promise.reject(new Error("no call is made in this test")),
  call: () => Promise.reject(new Error("no call is made in this test")),
};
const actor = createActor Promise>>(
  ledger.actor,
  "aaaaa-aa",
  transport,
);
assert.deepStrictEqual(
  Object.keys(actor),
  [...serviceMethods(ledger.actor).keys()],
  "same method names, same order",
);

Because a transport is an ordinary value, wrapping one composes. There is deliberately no logging hook on httpTransport; this is the intended way to observe traffic, and the same shape works for retries, request recording, or routing calls at different hosts.

import type { CallTarget, Transport } from "@candid-core/schema/actor";

function recording(inner: Transport, log: string[]): Transport {
  const through = (
    path: "query" | "call",
    target: CallTarget,
    arg: Uint8Array,
  ): Promise => {
    log.push(`${path} ${target.canisterId}.${target.methodName}`);
    return inner[path](target, arg);
  };
  return {
    query: (target, arg) => through("query", target, arg),
    call: (target, arg) => through("call", target, arg),
  };
}

const log: string[] = [];
const icrc = createActor(
  ledger.actor,
  "ryjl3-tyaaa-aaaaa-aaaba-cai",
  recording(httpTransport({ host: "https://icp-api.io" }), log),
);

The project's own integration test goes one step further: its transport decodes each request's argument bytes with the same schemas and encodes its reply with them, so a byte-level disagreement anywhere in the chain fails loudly, with no live network involved.

What this layer does not do

Everything an agent does beyond moving bytes stays on the agent's side of the pipe. The actor layer owns the DIDL message and nothing else. It does not:

  • Hold an identity or sign anything. Keys, delegations and signing belong to the agent you build. With httpTransport, that means constructing an HttpAgent yourself and passing it as agent.
  • Construct the ingress envelope. Request ids, ingress expiry, nonces and the read-state polling loop are the agent's. The adapter's call hands agent.update a method name and argument bytes, and takes back a reply.
  • Verify certificates or query signatures. The agent does that, against the root key it was configured with. httpTransport passes rootKey through and otherwise stays out of it.
  • Classify or retry rejects. See the failure styles above.
  • Carry per-call options. A CallTarget holds exactly canisterId, methodName and an optional effectiveCanisterId. No timeout or deadline travels through the pipe.

ActorOptions.effectiveCanisterId is read once when the actor is built and copied into every method's call target, so one actor cannot vary its routing target between calls. For management-canister work, where the effective target changes per call, build a CallTarget and drive the transport directly.
